PART 1 - WHAT WAS BUILT (AUDIT TRAIL)
================================================================================

1.1 SCOPE
Built a deterministic automated trading platform with AI attached as an
advisory/veto layer rather than a decision-maker. Five commits:

  043a1b0  Phase 0/1 engineering foundation
  7bf3bdb  Architecture amendment: automated execution, async agents, brokers
  65439e1  Robinhood history capture + strategy v1
  9c708bd  Backtest of strategy v1
  09949bc  Robustness analysis + fingerprint cache bug fix

Final state: 350 tests passing, mypy --strict clean over 92 files, ruff clean,
pip-audit clean, bandit clean. 8 architecture decision records.

1.2 THE AUTHORITY MODEL (the core idea)
One rule drives everything: deterministic code decides, AI reviews, humans
approve the envelope rather than each trade.

  Layer            May do                        May never do
  ---------------  ----------------------------  ------------------------------
  Strategy engine  Author every trading param    Read clock/network/global state
  Risk engine      Approve or reject             Resize, re-stop, re-target
  Agent layer      Veto (from cache); publish    Alter any param; create a trade;
                   context                       change mode; clear a kill switch
  Final validator  Refuse an order               Be overridden (no flag exists)
  Execution        Validate, translate, transmit Compute/round/adjust anything
  Broker adapter   Translate to a venue          Reinterpret what was asked for
  Human            Approve control plane and     -
                   strategy promotions

Each row is enforced by types and proven by tests, not by convention.

1.3 KEY STRUCTURAL MECHANISMS
- Every record crossing a layer boundary is frozen (immutable) and closed
  (extra="forbid"), so a downstream layer can neither mutate an upstream
  decision nor smuggle an extra field into it.
- float is REJECTED for money and size, not coerced. Decimal(0.1) != Decimal("0.1"),
  and a hash over a silently-widened float is not reproducible.
- No hidden inputs: no wall-clock defaults, no uuid4() defaults. Identifiers are
  derived (UUIDv5) from the inputs that produced the record, so replaying the
  same inputs produces byte-identical records.
- Every authoritative record exposes a SHA-256 "authoritative fingerprint" over
  the fields that determine what the market would actually feel. Downstream
  layers BIND to that fingerprint. Swapping a bigger trade in after approval is
  a caught error, not a silent success.
- The agent layer has no field capable of expressing a size, stop or target.
  The prohibition is derived from the candidate model itself, so adding a new
  trading parameter automatically extends it. An import-time assertion fails the
  package if that is ever violated.
- The final validator runs 25 hard gates before every submission. There is no
  force flag, no skip_checks, no agent path around it - asserted structurally by
  inspecting the function signature in a test.
- Kill switches are easy to engage and hard to clear. Automation may trip one.
  Only two triggers (broker unavailable, stale market data) may be cleared
  automatically, because both describe a directly observable transient
  condition. Everything else needs a named human.
- A broker timeout is treated as UNKNOWN state, not failure. The order may be
  working. The engine records it, halts the strategy, and reconciles. It never
  retries - retrying is how one intended position becomes two.

1.4 ARCHITECTURE DECISION RECORDS
  ADR-001  Deterministic trading authority

  ADR-003  Immutable raw data (write-once, content-addressed evidence)
  ADR-004  Strategy versioning (a behaviour change is a new version, never an edit)

  ADR-006  Asynchronous agent context
  ADR-007  Broker abstraction
  ADR-008  Automated execution, hard gates, where human authority moved

1.5 THE AMENDMENT (why Claude left the execution path)
Originally the agent sat inline: strategy -> risk -> Claude -> execution. That
put a variable-latency, externally-hosted, rate-limited dependency between a
signal and a fill. Three consequences, none about safety:
  - latency: an inference is hundreds of ms to seconds; the setup may be gone
  - availability: if Claude is down, the trading system is down
  - non-determinism at the wrong moment: execution itself becomes irreproducible

Now agents analyse on their own schedule and PUBLISH expiring context into a
store. The execution path reads a cache (a dict lookup) and never waits. Every
context carries a mandatory expiry, and the control plane sets an independent
staleness ceiling so a generous publisher cannot keep an opinion alive forever.

Three fallback policies exist, with NO default, because choosing between them is
a risk decision reserved for a human:
  REQUIRE_VALID_AGENT_CONTEXT   silent -> block, expired -> block, unhealthy -> block
  ALLOW_WITHOUT_AGENT_CONTEXT   silent -> trade, expired -> trade, unhealthy -> trade
  FAIL_CLOSED_ON_AGENT_FAILURE  silent -> trade, expired -> block, unhealthy -> block

The third exists because "never spoke" and "was speaking and stopped" are
different facts.

A valid veto blocks under ALL three policies. That is the agent's one power and
no configuration disables it.

Proven directly by test: the full pipeline runs and trades with no agent store
attached at all.

2.4 BEHAVIOURAL PATTERNS IN THE DATA
  - ZERO stop orders across 8 years and 141 orders. Not one.
  - 17 of 19 equity orders were MARKET orders (pays the spread invisibly).
  - All 122 option orders were single-leg long calls (64) or puts (58).
    No spreads, no defined-risk structures.
  - 55 of 87 option opens were 0DTE (same-day expiry).
  - Option concentration: QQQ 30, MSTR 22, SPY 11, HOOD 11, OPEN 9, NVDA 6.
  - Exactly one agentic order has ever existed: a cancelled limit buy of F at
    11.06 on 2026-07-14. No agentic order has ever filled.

2.5 THE DIAGNOSIS
A 24% win rate is survivable - trend systems live there. A 24% win rate with a
0.237 payoff ratio is not. That is roughly -$303 of expectancy per trade.

The mechanism is one line of the data: the average loss is FOUR TIMES the
average win. Losers were held; winners were cut.

That is a stop-loss problem, not a stock-picking problem. It was the only
finding specific enough to design against.


================================================================================
PART 3 - STRATEGY V1 (trend_breakout@1.0.0)
================================================================================

3.1 DESIGN, AND WHY EACH CHOICE
Every choice is the structural opposite of the loss mechanism above.

  Mandatory stop priced before entry  - history contained none; largest change
  Trend continuation, not mean revert - mean reversion buys weakness, which IS
                                        the -$12,987 mechanism
  Fixed 1.5:1 reward-to-risk target   - directly inverts the 0.237 payoff ratio
  Limit orders, never market          - 17/19 were market orders
  Multi-day holds                     - a sub-$25k margin account is PDT-capped
                                        at 3 day trades / 5 business days, so it
                                        CANNOT day-trade; also the opposite of 0DTE
  Volatility band 1%-6% ATR           - below 1% the stop sits inside the noise
  One position per symbol, long only  - no stacking, shorting or leverage
  Risk-based sizing at 0.5% of equity - size follows the stop, not conviction

3.2 THE RULES
  Entry (ALL must hold on the evaluation bar):
    1. close > SMA(200)
    2. SMA(50) > SMA(200)
    3. close > highest close of prior 20 bars
    4. 0.01 <= ATR(14)/close <= 0.06
    5. no open position in the symbol
    6. >= 200 bars of history available

  Order:  BUY, LIMIT at signal close, DAY
  Stop:   entry - 2.0 x ATR(14)
  Target: entry + 3.0 x ATR(14)   (reward:risk = 1.5)
  Size:   floor(0.005 x allocated_equity / (entry - stop)), whole shares
          fewer than 1 share => no trade

  Anything it cannot evaluate produces an explicit NoTrade with a reason code
  (INSUFFICIENT_DATA / FILTERED_BY_REGIME / NO_SETUP), never a silent skip.

  Parameters are conventional textbook defaults and were NEVER TUNED. This was
  deliberate: there is no strategy-relevant price history in the account record,
  so tuning against it would be fitting noise.

3.3 WHAT IT DOES NOT DO
  - No exits beyond stop and target. No trailing stop, no time stop, no partial
    profit-taking. Live position lifecycle management is NOT BUILT.
  - No shorts, no options, no crypto (all three appear in the loss record).
  - No universe selection - instruments come from human-approved config, because
    a strategy that picks its own instruments can escape a limit by picking a
    new one.

PART 4 - BACKTEST RESULTS
================================================================================

4.1 METHOD
  Data:      Robinhood daily bars, split-adjusted, 2015-01-02 to 2026-08-07
             (2,916 bars per symbol, 19 symbols)
  Entry:     limit at signal close, exactly as the strategy specifies
  Costs:     0.02% slippage per side
  Look-ahead: none - the strategy sees only bars strictly before the decision
             point, bounded by its own required_history()

  THREE DELIBERATELY PESSIMISTIC MODELLING CHOICES:
    1. Intrabar ambiguity always resolves to the STOP. When a daily bar's low
       reaches the stop and its high reaches the target, the order of touches is
       unknowable from daily data, so the worse reading is assumed every time.
    2. Gaps fill at the OPEN, not the level. A gap through the stop costs more
       than the stop. Assuming otherwise invents money.
    3. Unfilled limits count as MISSED, not lost. Conflating a missed trade with
       a losing one overstates both win rate and trade count.

4.2 HEADLINE RESULT AND THE SELECTION-BIAS CONTROL

  Universe                            Trades  WinRate  Payoff  Expect_R  t-stat
  ----------------------------------  ------  -------  ------  --------  ------
  10 megacaps/ETFs (I CHOSE THESE)       592    50.0%    1.62   +0.301     5.63
  9 large-cap laggards (CONTROL)         360    40.3%    1.63   +0.058     0.83
  Combined 19 symbols                    949    46.3%    1.62   +0.200     4.69

  Break-even win rate is 38.2%.

  Universe A (chosen): SPY QQQ IWM AAPL MSFT NVDA JPM XOM JNJ HD
  Universe B (control, deliberate underperformers): INTC PFE T VZ F NKE DIS
                                                    PYPL MMM

  THE CONTROL IS THE FINDING. On symbols not chosen for having done well,
  expectancy is statistically indistinguishable from zero. The gap between
  +0.301 and +0.058 is selection bias, not edge.

  Neither universe is unbiased - the laggards were also picked with hindsight,
  which biases THAT number down. The truth is somewhere between.

4.3 TIME SPLITS (universe A)
  Period                Trades  WinRate  Expect_R
  --------------------  ------  -------  --------
  2015-2020                288    52.8%   +0.381
  2021-2026 (holdout)      307    47.2%   +0.222
  2022 bear only            10    10.0%   -0.729

  The regime filter did its job in 2022: 10 trades ALL YEAR instead of ~55. It
  lost 7.3 R, which at 0.5% risk is -3.7% of the account in the worst year of
  the sample.

4.4 CONCURRENT POSITION SENSITIVITY (combined 19 symbols)
  This turned out to be the single most important result.

  Max positions   Trades  Expect_R  t-stat   Total_R
  -------------   ------  --------  ------   -------
  1                  181   +0.108     1.13     +19.5   <- NOT significant
  2                  308   +0.127     1.69     +39.0
  3                  440   +0.180     2.89     +79.3
  5                  665   +0.232     4.58    +154.5
  8                  879   +0.211     4.79    +185.6
  unlimited          949   +0.200     4.69    +189.6

  At ONE position (which is what the risk limits originally specified) the edge
  is not distinguishable from zero: 181 trades in 11.6 years, about 16 a year,
  roughly 0.84% a year at 0.5% risk. The machinery would work; the strategy
  would not be worth running.

  Significance appears at 3 positions. Benefit plateaus around 5.

4.5 PARAMETER ROBUSTNESS (at max 5 concurrent positions)
  One parameter moved at a time from the base configuration.

  Variant                                Trades  WinRate  Expect_R  t-stat
  -------------------------------------  ------  -------  --------  ------
  BASE stop2.0 target3.0 break20 trend200   665    37.9%   +0.232     4.58
  stop 1.5                                  759    31.4%   +0.269     4.76
  stop 2.5                                  606    43.9%   +0.141     2.99
  stop 3.0 / target 4.5                     390    39.0%   +0.170     2.60
  target 2.5 (R:R 1.25)                     750    42.1%   +0.147     3.41
  target 4.0 (R:R 2.0)                      513    32.2%   +0.247     3.69
  target 6.0 (R:R 3.0)                      375    24.1%   +0.415     4.12
  breakout 10                               684    38.7%   +0.149     2.99
  breakout 40                               611    37.9%   +0.228     4.32
  breakout 60                               582    37.7%   +0.254     4.66
  trend 100                                 662    38.4%   +0.242     4.68
  trend 150                                 649    38.7%   +0.224     4.36
  trend 250                                 649    38.1%   +0.217     4.23

  ALL THIRTEEN POSITIVE. Range +0.14 to +0.41 R, t from 2.6 to 4.8.
  That is a PLATEAU, not a spike - the signature of a real effect rather than a
  curve fit. If the base parameters had been fitted to this data, the
  neighbours would fall off a cliff. They don't.

  The best cell (target 6.0, +0.415 R) was deliberately NOT adopted. Picking it
  because it scored highest here is exactly the overfitting the test detects.

4.6 WHAT THE BACKTEST DOES NOT COVER
  - SURVIVORSHIP. Both universes contain only companies that still exist. No
    delistings, no bankruptcies, no acquisitions. This biases results UP and is
    the largest remaining unknown. A proper test needs point-in-time index
    constituents.
  - No walk-forward was run. A classic walk-forward was skipped DELIBERATELY:
    the parameters were never tuned, so re-fitting per window would introduce
    overfitting where there currently is none. The robustness sweep in 4.5 tests
    the same concern more directly.
  - 11.6 years containing one bull market with two corrections. 2022 is the only
    real bear and produced 10 trades.
  - Liquidity and spread assumed benign - true for these 19 names, not generally.

4.7 VERDICT
  The edge is real, robust to parameter choice, and survives out of sample -
  and it is SMALL. At 5 concurrent positions and 0.5% risk, +154 R over 11.6
  years is roughly 6.7% a year on risk deployed, before tax, and ignoring the
  survivorship bias which inflates even that.

  Enough to justify SHADOW mode to validate the machinery end to end.
  NOT enough to justify funding on this evidence.

PART 5 - ENGINEERING LEARNINGS
================================================================================

5.1 A CACHE ON A SECURITY BOUNDARY IS A CORRECTNESS HOLE
Memoising the authoritative fingerprint made backtests 5.5x faster (3m16s ->
36s). But Pydantic's model_copy carries private attributes onto the copy, so:

    candidate.model_copy(update={"quantity": 1000})

reported the ORIGINAL's fingerprint. Every downstream binding the authority
model depends on - risk approval, agent review, order intent - would have
accepted a 1000-share trade as the 10-share one that was approved.

Seven existing invariant tests failed immediately. That is the single best
piece of evidence in the whole project that the guard rails were worth their
cost: a subtle, silent, catastrophic bug was caught by tests written weeks
earlier for a different reason.

Fix: override model_copy to drop the cached digest whenever fields change; a
copy with no update is content-identical so its digest is kept. Plus 13
regression tests covering mutating copies, plain and deep copies, revalidation
round-trips, and detection of history reordering/truncation/tampering.

LESSON: caching is safe on immutable data ONLY if every path that produces a
derived object is accounted for. Enumerate the paths, don't assume there is one.

5.2 SELECTION BIAS IS BIGGER THAN YOU THINK
Choosing 10 well-known large caps produced +0.301 R at t=5.63 - a result that
looks publication-grade. A control universe of deliberate underperformers gave
+0.058 R at t=0.83.

The entire apparent edge, and then some, came from the symbol list.

LESSON: if you pick the universe, you have already picked the answer. Always
run a control universe chosen with the OPPOSITE bias, and treat the gap as your
error bar.

5.3 THE PORTFOLIO CONSTRAINT CAN ERASE THE STRATEGY
A per-symbol backtest silently assumes unlimited concurrent positions. The real
risk limit allowed ONE. That single difference took the strategy from
+0.200 R / t=4.69 to +0.108 R / t=1.13 - from significant to noise.

LESSON: backtest the PORTFOLIO, not the signal. A signal-level result is an
upper bound that may be unreachable under the constraints you actually operate
under.

5.4 REPORT THE T-STATISTIC, NOT JUST THE EXPECTANCY
+0.058 R per trade looks positive and is meaningless at 360 trades. Adding a
t-statistic to the report turned three separate "looks good" results into
"one is real, two are noise" at a glance.

LESSON: an expectancy without a standard error is a story, not a measurement.

5.5 PESSIMISTIC SIMULATION IS THE ONLY USEFUL KIND
Intrabar ambiguity resolving to the stop, gaps filling at the open, unfilled
limits counted as missed rather than lost, slippage charged both sides. Each
choice individually makes results worse; collectively they make results
believable.

LESSON: a backtest that flatters a strategy produces confidence rather than
information, which is worse than having no backtest at all.

5.6 CONSTRAINTS FOUND IN DATA BEAT CONSTRAINTS ASSUMED IN DESIGN
Three risk limits chosen as "conservative placeholders" turned out to make the
strategy unrunnable rather than merely safe:

  max_open_positions                  1    -> needs 3-5 (edge vanishes at 1)
  max_open_portfolio_risk_fraction    0.01 -> capped the book at 2 positions,
                                              contradicting the fix above
  max_consecutive_losses              6    -> 10-17 actually observed; the kill
                                              switch would trip several times a year

LESSON: "conservative" is not a safe default. A limit that silently prevents the
system from functioning is a bug wearing a safety costume. Derive limits from
measured behaviour, then decide whether to tighten them.

5.7 REGULATORY CONSTRAINTS SHAPE STRATEGY DESIGN BEFORE ALPHA DOES
A sub-$25,000 margin account is capped at 3 day trades per rolling 5 business
days (US pattern day trader rule). That eliminates an entire class of strategy
before any question of edge arises.

LESSON: enumerate the hard constraints (account size, regulation, broker
capability, agent access) FIRST. They narrow the design space more than any
performance consideration.

5.8 MAKE PROHIBITIONS STRUCTURAL, NOT PROCEDURAL
The strongest guarantees in this system are the ones where violating the rule
requires changing a type rather than remembering a check:
  - the agent has no field for a stop, so it cannot set one
  - the forbidden-field set is DERIVED from the candidate model, so adding a new
    trading parameter extends the prohibition automatically
  - an import-time assertion fails the package if that is ever violated
  - the Robinhood adapter declares NO capabilities, so the engine refuses it
    before an order is even built - the raise in submit_order is a second,
    redundant stop

LESSON: prefer "cannot" over "must not". A convention degrades; a type does not.

5.9 A TIMEOUT IS NOT A FAILURE
The single most dangerous broker response is the one where you do not know what
happened. Treating a timeout as failure and retrying is how one intended
position becomes two.

LESSON: type your errors by what they TELL you - definite refusal, definitely
nothing sent, or genuinely unknown - and make the unknown case halt rather than
retry.

5.10 PER-TRADE HUMAN APPROVAL IS THEATRE
An operator approving the fortieth mechanically identical trade of the day is
not evaluating it. The control that exists on paper is not the control that
exists in practice, and the gap is invisible because the approvals keep being
granted.

Replaced with: humans approve the ENVELOPE (execution mode, enabled strategies,
instruments, allocation, sessions, risk limits, promotions), and 25
deterministic gates run on every single order with no override.

LESSON: automate the check that runs every time; reserve human attention for the
decisions that change what is possible, not the ones that repeat.

PART 6 - OPEN DECISIONS AND BLOCKERS
================================================================================

6.1 BLOCKERS
  B-1  docs/PRD.md does not exist in the repo. Everything was built from task
       briefs. Unknown whether the PRD contradicts any of it.
  B-2  Only 19 symbols of price history captured; no survivorship-free universe.
  B-3  No production risk values chosen (see D-1).
  B-5  The funded account ($6,474) is NOT agent-accessible. The only
       agent-accessible account holds $157.94, at which the strategy correctly
       refuses every trade because the risk budget buys less than one share.
       Automation currently has nothing to run against.

6.2 DECISIONS REQUIRING A HUMAN
  D-1  Production risk limits (13 required fields, no defaults exist in code).
       Now higher-stakes: these limits replaced per-trade confirmation as the
       backstop.
  D-2  Broker and market data vendor. Blocks a real adapter, paper trading, and
       any survivorship-free dataset.
  D-3  Are recorded approvals sufficient, or are cryptographic signatures needed?
  D-4  Regime taxonomy - the five states exist, the boundaries do not.
  D-5  What evidence gates PAPER -> LIMITED_LIVE?
  D-6  Scope of the Claude conversation history export.
  D-8  Which AgentContextPolicy for production (three implemented, no default).
  Universe: which instruments the strategy may trade (control-plane config).

6.3 KNOWN GAPS IN THE SYSTEM
  Q-1  code_fingerprint is supplied by hand; nothing computes it automatically
  Q-2  no veto-rate monitoring; a broken agent degrades silently
  Q-3  model_copy can still forge a fully-consistent approval (mitigated by
       ledger provenance, not eliminated)
  Q-5  RiskDecision is not persisted before the OrderIntent is built
  Q-6  multi-fill reconciliation undefined until real fill payloads are inspected
  Q-7  POSITION LIFECYCLE AFTER ENTRY IS NOT BUILT. The system can open a
       position; it cannot manage the exit beyond a native bracket order.
  Q-8  no start-up reconciliation sweep comparing venue state to expected state
  Registry, promotion history and control-plane revisions are all in-process
  only and do not survive a restart.


================================================================================
PART 7 - THINGS DELIBERATELY NOT DONE
================================================================================
  - No live trading. ExecutionMode.LIVE is refused by the control plane and no
    adapter declares live capability.
  - No autonomous brokerage execution. The Robinhood adapter declares zero
    capabilities.
  - No credentials anywhere in the codebase. MCP sessions are host-supplied;
    database URLs come from the environment and are redacted before logging.
  - No microservices, no message broker, no async. One repo, one process.
  - No P&L simulation in the replay harness beyond the explicit backtest
    simulator - a number that looks like a return but isn't is worse than none.
  - No parameter optimisation. Defaults were fixed before the first backtest run
    and were not changed afterwards, including after seeing a better cell.
